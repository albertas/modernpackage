# Design Discussion

## Current State

The test suite is a single file, `tests/test_main.py` (8 unit tests), with an
empty `tests/__init__.py:1`, **no `conftest.py`**, and no fixtures or markers
anywhere (research Q1, Q6).

- **Mocking is already correct.** Every external-effect seam in
  `modernpackage/main.py` is patched in tests via `unittest.mock.patch` used as a
  context manager on the defining module path: `Popen`
  (`tests/test_main.py:42`), `print` (`:13`, `:61`), `ArgumentParser`
  (`:12`, `:49`, `:60`), and `sys.argv` (`:30`, `:36`). No test touches the
  network, a subprocess, or the filesystem (research Q1, Q2). The only effectful
  production path — `init_new_package` running `git clone` + `make init` via
  `Popen` (`main.py:41-51`) — is exercised only through a mocked `Popen`
  (`tests/test_main.py:41-44`).
- **No parallelism.** pytest runs single-process. There is no `-n`,
  `--numprocesses`, or `nproc` expression in `Justfile`, `Makefile`,
  `pyproject.toml`, or CI (research Q3). `pytest-xdist` is **not** a declared or
  installed dependency anywhere (research Q4).
- **Test config** is a single `addopts` line:
  `--cov=modernpackage --no-cov-on-fail --cov-fail-under=95.0`
  (`pyproject.toml:40`). No `testpaths`, no `markers`.
- **Two runners coexist.** `Justfile` `test *args: sync` → `uv run pytest {{args}}`
  (`Justfile:10-11`); `Makefile` `test: .venv` → `.venv/bin/pytest $(TEST_NAME)`.
  CI (GitLab + GitHub) runs `make check`; local convention favors the Justfile
  (research Q3, Cross-Cutting).
- **No e2e/integration tests** exist and no marker convention distinguishes them
  (research Q6).
- **Convention already documented:** `BACKLOG.md:8` and the vupi sibling source
  (`vupi/_code_quality.py:49`) both use the literal recipe
  `uv run pytest -n "$(nproc --ignore=1)" {{args}}` — "all cores minus one"
  (research Q5).

## Desired End State

1. `pytest-xdist` is a declared test dependency and installed in the dev env.
2. `just test` runs the suite in parallel across `nproc --ignore=1` workers
   (all-but-one core), matching the documented sibling convention.
3. A registered `e2e` marker exists; the default test run **excludes** `e2e`
   tests so only mocked unit tests run by default, and real external calls are
   reserved for an explicit `just test-e2e` invocation.
4. Coverage gate (95%) continues to pass under xdist.

**Verification:** `just test` shows xdist workers (`gw0..gwN-1`) in output and
passes with coverage ≥ 95%; `pytest --markers` lists `e2e`; running with a
deliberate `@pytest.mark.e2e` test confirms it is skipped by default and selected
by `just test-e2e`.

## Patterns to Follow

- **Patch-the-seam-as-context-manager** mocking on the defining module path:
  `patch('modernpackage.main.Popen')` (`tests/test_main.py:42`). Any new e2e
  scaffolding must NOT undo this for unit tests — keep them fully mocked.
- **Justfile recipe shape**: every recipe depends on `sync` and shells out via
  `uv run` (`Justfile:10-20`). The parallel recipe must follow the exact
  documented form `uv run pytest -n "$(nproc --ignore=1)" {{args}}`
  (`BACKLOG.md:8`, `vupi/_code_quality.py:49`).
- **Single-quote / full-word style** per `pyproject.toml:57,60` and Code Best
  Practices; marker names lowercase (`e2e`).
- **Declare test deps in `[project.optional-dependencies].test`**
  (`pyproject.toml:27-37`); `requirements-dev.txt` is autogenerated by
  `uv pip compile --all-extras` (`requirements-dev.txt:1-2`) — regenerate it,
  never hand-edit.

**Patterns to NOT follow / flag:**

- Do **not** put parallelism in `pyproject.toml addopts`. `addopts` cannot
  shell-expand `$(nproc --ignore=1)`; `-n auto`/`-n logical` would use *all*
  cores, contradicting the "all-but-one" requirement. Parallelism belongs in the
  shell recipe (research Q5).
- Do **not** rely on the `Makefile` as the canonical runner long-term —
  `BACKLOG.md:34` records intent to merge it into the Justfile — but it is what
  CI invokes today, so it must not be left broken.

## Design Decisions

1. **Where parallelism lives — Justfile recipe, not addopts.** Use
   `uv run pytest -n "$(nproc --ignore=1)" {{args}}` in `Justfile` `test`. This
   is the only place `$(nproc --ignore=1)` can be evaluated and exactly matches
   the documented convention (research Q5). *Assumption:* "all-but-one cores"
   means `nproc --ignore=1`, the established project idiom.
2. **Add `pytest-xdist` to `[project.optional-dependencies].test`** and
   regenerate `requirements-dev.txt` via `uv pip compile --all-extras`. Keeps the
   declared/locked dependency sources consistent (research Q4).
3. **e2e separation via a registered marker + default deselection.** Register
   `e2e` under `[tool.pytest.ini_options].markers` and add `-m 'not e2e'` to
   `addopts` so the default run is mocked-only. Add a `just test-e2e` recipe that
   runs `uv run pytest -m e2e {{args}}` (command-line `-m` overrides the addopts
   default). *Assumption:* no real e2e test is authored now (none exists, Q6); we
   establish the convention/infrastructure so future real-call tests have a home.
4. **Keep existing unit tests untouched.** They are already fully mocked
   (research Q1, Q2); the task's "ensure unit tests are mocked" is already
   satisfied, so no test-body edits are needed — only infrastructure.
5. **Update the Makefile `test` recipe too.** Add `-n "$(nproc --ignore=1)"` to
   `.venv/bin/pytest` so CI (`make check`) also runs parallel + deterministic.
   *Assumption:* keeping CI behavior aligned with local is in scope despite the
   Makefile→Justfile merge being a separate backlog item.
6. **Coverage stays as-is.** `pytest-cov` supports xdist transparently; no
   `--cov` flag changes needed (research Q3).

## What We're NOT Doing

- Not writing an actual real-network e2e test (no `git clone`/`make init` against
  GitHub). Only the marker + recipe scaffolding is added.
- Not merging the Makefile into the Justfile (`BACKLOG.md:34` is a separate task).
- Not adding `conftest.py`, fixtures, or `testpaths` unless required to register
  the marker (marker registration lives in `pyproject.toml`, so none expected).
- Not changing the 95% coverage threshold or any lint/type config.
- Not adding test-ordering plugins (`pytest-randomly`, `pytest-forked`); tests
  are already independent, which is what makes xdist safe here.
- Not touching `modernpackage/main.py` production code.

## Open Risks

- **xdist + coverage interaction.** With few, fast tests the per-worker startup
  overhead may make `-n` *slower* in wall-clock than single-process; this is
  acceptable since the requirement is the parallel configuration, not a speedup
  on 8 tests. Verify coverage still aggregates to ≥ 95% across workers.
- **`nproc` availability.** `nproc --ignore=1` assumes a GNU coreutils `nproc`
  (present in CI `python:latest`/GitHub runners). On a 1-core machine
  `nproc --ignore=1` yields `0`; xdist treats `-n 0` as disabled — acceptable
  fallback, worth a note.
- **Makefile parallelism in CI.** If the CI image lacks `pytest-xdist` until the
  regenerated `requirements-dev.txt`/`.venv` is in place, the `-n` flag will
  error; ensure the dependency change lands before the recipe change is relied on.
- **Marker strictness.** If a future config adds `filterwarnings = error`, an
  unregistered marker would fail — registering `e2e` now pre-empts that.
