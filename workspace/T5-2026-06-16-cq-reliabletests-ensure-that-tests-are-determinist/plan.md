# Implementation Plan

## Overview

Make the test run deterministic-by-default and parallel: declare and install
`pytest-xdist`, run `just test` across `nproc --ignore=1` workers, register an
`e2e` marker that is deselected by default (mocked unit tests only) with an
explicit `just test-e2e` escape hatch, and align the CI-invoked `Makefile`
`test` recipe. No production code and no existing test bodies change.

## Phase 2: `e2e` marker + default deselection + `just test-e2e`

Register the `e2e` marker, make the default run mocked-only by deselecting
`e2e`, and add a recipe that selects only `e2e` tests. No real e2e test is
authored — only the convention/infrastructure (design decision 3).

### Changes

#### 1. Register the marker and deselect it by default
**File**: `pyproject.toml`
**Action**: modify

Extend `[tool.pytest.ini_options]` (lines 39-40). Add a `markers` array and
append `-m 'not e2e'` to the existing `addopts` string. Parallelism stays in


**File**: `Justfile`

```justfile

```

## Phase 3: Align the CI-invoked Makefile

Add parallelism to the `Makefile` `test` recipe so `make check` (what GitLab +
GitHub CI run) also executes parallel and deterministic, consistent with
`just test` (design decision 5). Depends on Phase 1's dependency landing so
`-n` resolves.

### Changes

#### 1. Parallelize the Makefile test recipe
**File**: `Makefile`
**Action**: modify

Change the `test` recipe body (line 47). Keep the `.venv` prerequisite and the
`$(TEST_NAME)` passthrough:

```makefile
test: .venv
	.venv/bin/pytest -n "$(nproc --ignore=1)" $(TEST_NAME)
```

Note: `$(nproc --ignore=1)` here is a shell command substitution executed by the
recipe shell at runtime, not a Make variable — Make passes the literal string to
the shell. (Make variable refs use `$(VAR)`; `$(nproc ...)` is not a defined Make
variable so it would expand to empty if Make intercepted it. Because the recipe
runs in a shell, `$(...)` is the shell's command substitution. This matches the
Justfile form, which also relies on shell substitution.)

DEVIATION: The plan says `$(nproc --ignore=1)` but in GNU Make recipes `$(...)` is
expanded by Make as a variable reference before the shell sees it — since `nproc
--ignore=1` is not a Make variable, it would expand to empty, giving pytest `-n ""`
which errors. The correct syntax is `$$(nproc --ignore=1)` (double `$$` so Make
passes `$(nproc --ignore=1)` to the shell). The Makefile already uses this `$$`
pattern at line 8 (`$$count`, `$$((count + 1))`). Implemented as
`.venv/bin/pytest -n "$$(nproc --ignore=1)" $(TEST_NAME)`.

## Assumptions Resolved (no open questions)

1. **"all-but-one cores" = `nproc --ignore=1`** — the established project idiom
   (BACKLOG.md:8, vupi `_code_quality.py:49`; design decision 1).
2. **No real e2e test authored now** — only marker + recipe scaffolding; none
   exists today (research Q6; design decision 3).
3. **Requirements regeneration uses `make compile`** (the project's own recipe,
   `uv pip compile --all-extras`) rather than a hand-written invocation, with a
   documented manual fallback if codegen/network fails.
4. **Existing unit tests stay untouched** — already fully mocked (research Q1,
   Q2; design decision 4).
5. **Coverage config unchanged** — `pytest-cov` aggregates across xdist workers
   transparently (design decision 6).
6. **`-m 'not e2e'` lives in `addopts`, parallelism lives in the shell recipes**
   — `addopts` cannot shell-expand `$(nproc --ignore=1)` (design "Patterns to
   NOT follow").

## Edge Notes (from design Open Risks)

- On a 1-core machine `nproc --ignore=1` → `0`; xdist treats `-n 0` as disabled
  (runs single-process) — acceptable fallback, not an error.
- Phase 1's dependency change MUST be committed/installed before Phase 3's `-n`
  flag is relied on in CI, or `pytest -n` will error in the CI image.
- Registering `e2e` now pre-empts a future `filterwarnings = error` turning an
  unregistered marker into a failure.
