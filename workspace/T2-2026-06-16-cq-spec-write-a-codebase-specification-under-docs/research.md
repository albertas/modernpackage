# Research Findings

Scope: the `modernpackage/` package, `tests/`, and top-level build/config files.
This is a small CLI tool that scaffolds new Python packages by cloning itself.

## Q1: CLI entry point, arguments/options, and control flow

### Findings
- Two console-script entry points map to the same callable `modernpackage.main:main`:
  `modernpackage` and `mp` (`pyproject.toml:24-26`, `[project.scripts]`).
- `main()` is the orchestrator (`modernpackage/main.py:54-62`):
  - Calls `parse_args()` (`main.py:56`).
  - If `parsed_args.version` → `print(f'modernpackage {__version__}')` (`main.py:58-59`).
  - `elif parsed_args.package_name` → `init_new_package(package_name=...)` (`main.py:61-62`).
  - If neither flag nor positional given, `main()` does nothing (no else branch).
- Argument parsing in `parse_args()` (`main.py:18-34`) uses `argparse.ArgumentParser`:
  - `-v` / `--version`: `action='store_true'`, `default=False` (`main.py:21-27`).
  - `package_name`: positional, `nargs='?'` (optional), `type=check_alpha_numeric`
    (`main.py:28-33`).
- Validation: `check_alpha_numeric()` rejects non-alphanumeric names by raising
  `ArgumentTypeError('Non-AlphaNumeric package name')` via `str.isalnum()`
  (`main.py:10-15`).
- `__version__` is imported from the package `__init__` (`main.py:7`,
  `modernpackage/__init__.py:3` → `'0.0.9'`).
- Note: there is a typo in the positional help text ("pacakge", `main.py:30`).

## Q2: Package-initialisation flow

### Findings
- `init_new_package(package_name)` (`main.py:37-51`) runs two external commands via
  `subprocess.Popen`:
  1. `git clone https://github.com/albertas/modernpackage <cwd>/<package_name>`
     (`main.py:41-46`). Target path is `Path.cwd() / package_name` (`main.py:39`).
  2. `make init <package_name>` run with `cwd=new_package_path` (`main.py:48-51`).
  - Both use `stdin=PIPE, stdout=PIPE`; output captured via `.communicate()[0]`.
    The second call decodes stdout and splits on `'make:'` but discards the result
    (`main.py:51`) — no return value, no error handling.
  - `# noqa: S603/S607` suppress subprocess security lint warnings.
- The `Makefile` `init` target transforms the freshly cloned project
  (`Makefile:60-75`), with `args` defaulting via
  `args = $(or $(filter-out $@,$(MAKECMDGOALS)), "modernpackage")` (`Makefile:2`):
  - Detects OS (`OS := $(shell uname)`, `Makefile:4`).
  - Linux: `git grep -l 'modernpackage' | xargs sed -i 's/modernpackage/$(args)/g'`
    (`Makefile:62-64`). Darwin: same with BSD `sed -i ''` form (`Makefile:65-67`).
    Replaces all `modernpackage` string occurrences with the new name across tracked files.
  - Resets version to `0.0.1` in `modernpackage/__init__.py` via a digit-triplet
    `sed` regex (`Makefile:68`).
  - Renames the package directory: `mv modernpackage $(args)` (`Makefile:69`).
  - `rm -fr .git/ .venv` then re-inits git: `git init -b main .`, `git add .`,
    `git commit -m "Initial modern $(args) package setup"` (`Makefile:70-73`).
  - Prints a completion message and `-exit 0` (`Makefile:74-75`).
- The catch-all `%:` / `@:` rule (`Makefile:77-78`) lets the bare package-name token
  be passed as a make goal without error.

## Q3: Build, versioning, publishing, and requirements

### Findings
- Build backend: `hatchling` (`pyproject.toml:[build-system]`,
  `requires = ["hatchling"]`, `build-backend = "hatchling.build"`).
- Build inclusion: `[tool.hatch.build]` includes `**/*.py`, excludes `tests/**`.
- Version source: dynamic, `dynamic = ["version"]`; `[tool.hatch.version]`
  `path = "modernpackage/__init__.py"` reads `__version__ = '0.0.9'`
  (`modernpackage/__init__.py:3`).
- Entry-point scripts: `modernpackage` and `mp` → `modernpackage.main:main`
  (`pyproject.toml [project.scripts]`).
- Dependencies: runtime `dependencies = []` (none). Optional group
  `[project.optional-dependencies] test` lists `hatch, ruff, mypy, pip-audit,
  deadcode, pytest, pytest-cov, vupi>=0.0.6`.
- `requires-python = ">= 3.14"`.
- Publishing via `make publish` (`Makefile:22-25`): depends on `.venv`, clears
  `dist/*`, runs `.venv/bin/hatch build` then `.venv/bin/hatch -v publish`.
  `dist/` currently holds `modernpackage-0.0.8` wheel + sdist (older than `__init__`'s 0.0.9).
- `requirements.txt` (`requirements.txt:1-2`) is autogenerated by
  `uv pip compile pyproject.toml` and currently has **no pinned deps** (runtime deps empty).
- `requirements-dev.txt` autogenerated by `uv pip compile --all-extras`
  (`requirements-dev.txt:1-2`); pins the full transitive dev set (annotated-types,
  pydantic, anyio, mypy, claude-agent-sdk, mcp, etc.).
- Regeneration: `make compile` (`Makefile:53-55`) runs both `uv pip compile` commands
  (`-U` upgrade) writing `requirements.txt` and `requirements-dev.txt`.
- `[[tool.uv.index]]` adds a private GitLab PyPI index named `gitlab` (`pyproject.toml`).
- `uv.lock` (~202 KB) present as the uv lockfile.

## Q4: Developer tooling configuration and invocation

### Findings
- Tools configured in `pyproject.toml`:
  - **Ruff** (lint + format): `line-length = 88`; `[tool.ruff.lint] select = ["ALL"]`
    with ignores `D203, D213, COM812, ISC001, ANN101`; `flake8-quotes inline-quotes
    = 'single'`; `[tool.ruff.format]` single quotes + `docstring-code-format`;
    per-file ignore `tests/* = ["S101", "D"]` (allow asserts/no docstrings).
  - **mypy**: `strict = true`, `python_version = "3.14"`, `pretty`, `color_output`,
    `show_error_codes`, `warn_return_any`, `warn_unused_configs`; excludes
    `build, dist, .venv`.
  - **deadcode**: `ignore_names = ["main"]`, `exclude = ["tests"]`.
  - **pytest/coverage**: `[tool.pytest.ini_options] addopts = "--cov=. --no-cov-on-fail
    --cov-fail-under=50.0"` (coverage via pytest-cov; fails below 50%).
  - **pip-audit**: no config block; invoked with `--skip-editable`.
- `Makefile` targets (`Makefile:10, 27-47`):
  - `check: test lint mypy audit deadcode` (`Makefile:10`) — aggregate gate.
  - `fix: format fixlint` (`Makefile:11`).
  - `lint`: `ruff check modernpackage tests` (`Makefile:27-28`).
  - `fixlint`: `ruff check --fix ... --unsafe-fixes` + `deadcode --fix` (`Makefile:30-32`).
  - `format`: `ruff format modernpackage tests` (`Makefile:34-35`).
  - `mypy`: `mypy modernpackage tests` (`Makefile:37-38`).
  - `audit`: `pip-audit --skip-editable` (`Makefile:40-41`).
  - `deadcode`: `deadcode modernpackage tests` (`Makefile:43-44`).
  - `test`: `pytest $(TEST_NAME)` (`Makefile:46-47`).
  - All depend on `.venv` target (`Makefile:13-20`): installs uv if missing,
    `uv venv -p 3.14`, `uv pip sync requirements-dev.txt`, `uv pip install -e .[test]`.
- `Justfile` (`Justfile:1-4`) defines only a `lifecycle` recipe: sync deps then loop
  `uv run lifecycle --max-tasks 1 --prior-tasks "$count"`. The `Makefile` `lifecycle`
  target (`Makefile:6-8`) mirrors this. (Note: project README/CLAUDE.md reference
  `just check`/`just test`, but the current `Justfile` only contains `lifecycle`.)
- CI: GitHub Actions `.github/workflows/check-modernpackage-on-python311.yml` runs on
  push/PR to `main`, sets up Python 3.14, runs `make .venv` then `make check`.
  GitLab CI `.gitlab-ci.yml` uses `python:latest`, `make .venv` before_script,
  `make check` as the test job; caches `.cache/pip` with `RUFF_CACHE_DIR` override.

## Q5: Test structure, coverage, mocking/fixtures

### Findings
- Tests live in `tests/` with `tests/__init__.py` and a single test module
  `tests/test_main.py`.
- One test: `test_show_version()` (`tests/test_main.py:7-14`):
  - Patches `modernpackage.main.ArgumentParser` and `modernpackage.main.print`
    via `unittest.mock.patch` context managers (`test_main.py:8-11`).
  - Forces `argparse_mock().parse_args().version = True` (`test_main.py:12`),
    calls `main()`, asserts `print` called once with `f'modernpackage {__version__}'`
    (`test_main.py:13-14`).
- Coverage of behaviour: only the `--version` branch of `main()` is exercised.
  `check_alpha_numeric`, `init_new_package`, the package-name branch, and real
  arg parsing are **not** tested.
- No pytest fixtures or `conftest.py`; mocking is per-test `unittest.mock.patch`.
  Coverage gate is `--cov-fail-under=50.0` (`pyproject.toml`).
- A `.coverage` data file exists at repo root (artifact of a prior run).

## Q6: Overall file/module structure and relationships

### Findings
- Package: `modernpackage/__init__.py` (version constant) + `modernpackage/main.py`
  (CLI logic). `main.py` imports `__version__` from `__init__` (`main.py:7`).
- Tests: `tests/__init__.py`, `tests/test_main.py` import from `modernpackage`.
- Config/build: `pyproject.toml` is the single source for project metadata, scripts,
  build backend, version path, and all tool configs (ruff/mypy/deadcode/pytest/uv).
- Task aliases: `Makefile` (primary; recipes call `.venv/bin/*` tools and wrap
  git/make for scaffolding) and `Justfile` (only `lifecycle`).
- Dependency manifests: `requirements.txt` (runtime, empty) and
  `requirements-dev.txt` (full dev pins), both generated by `uv pip compile`;
  `uv.lock` is the uv lockfile.
- CI: `.github/workflows/check-modernpackage-on-python311.yml`, `.gitlab-ci.yml`,
  both run `make check`.
- Docs/meta: `README.md` (usage, toolset list, feature-request backlog),
  `BACKLOG.md`, `issues/`, `lifecycle_state.yml`, `workspace/` (lifecycle artifacts).
- Build output: `dist/` (0.0.8 wheel + sdist).
- Self-referential design: the CLI clones this very repo and runs `make init`, so the
  `Makefile` `init` target's string-rename + version-reset operates on a copy of this
  same structure (ties Q2 ↔ Q6).

## Cross-Cutting Observations
- The tool is self-replicating: `modernpackage/main.py` clones `albertas/modernpackage`
  and the `Makefile init` target rewrites every `modernpackage` token to the new name.
- `pyproject.toml` is the canonical config hub; `Makefile` is the canonical command
  hub. README and CLAUDE.md mention `just` workflows, but the present `Justfile` only
  has `lifecycle` — a divergence from the documented `make`-centric flow.
- Python 3.14 is targeted consistently (pyproject, mypy, Makefile `.venv`, CI).
- Single-quote style and `select=["ALL"]` reflect an intentionally strict lint posture.

## Open Areas
- `vupi` (dev dep, used by `lifecycle`/`uv run lifecycle`) is external to this repo;
  its behaviour is not defined in this codebase.
- `init_new_package` discards subprocess output and has no error handling; the README
  backlog (`README.md:57-76`) documents a known crash when git/network is unavailable —
  this describes existing behaviour, not a fix.
- Version drift: `__init__.py` is `0.0.9`, `dist/` holds `0.0.8` — no in-repo evidence
  of which is published to the configured index.
