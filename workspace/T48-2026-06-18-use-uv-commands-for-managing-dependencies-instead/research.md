# Research Findings

Facts about how this repo manages Python dependencies and orchestrates dev/CI
tasks. All references are `file:line`.

## Q1: How are dependencies declared/pinned across `pyproject.toml`, `uv.lock`, `requirements.txt`, `requirements-dev.txt`?

### Findings
- Runtime deps are empty: `dependencies = []` (`pyproject.toml:18`).
- One optional-dependencies group named `test` (`pyproject.toml:27-37`): `ruff`,
  `mypy`, `pip-audit`, `deadcode`, `pytest`, `pytest-cov`, `pytest-xdist`,
  `vupi>=0.0.7`. This is the only extra; there are no PEP 735 `[dependency-groups]`.
- A private index is declared: `[[tool.uv.index]]` name `gitlab`, URL
  `https://gitlab.com/api/v4/projects/niekas%2Fpackages/packages/pypi/simple`
  (`pyproject.toml:97-99`).
- `requirements.txt` is autogenerated and effectively empty — only the header
  comment `uv pip compile pyproject.toml -o requirements.txt` (`requirements.txt:1-2`),
  reflecting the empty runtime `dependencies`.
- `requirements-dev.txt` is autogenerated via `uv pip compile --all-extras`
  (`requirements-dev.txt:1-2`); it contains fully-pinned transitive dev/test deps
  (`==` pins with `# via` provenance), e.g. `mypy==2.1.0`, `pytest==9.1.0`,
  `vupi==0.0.8`, `ruff==0.15.17` (`requirements-dev.txt:3-198`). Direct deps are
  annotated `# via modernpackage (pyproject.toml)`.
- `uv.lock` is the uv-native lockfile (177 KB, `uv.lock`), regenerated alongside
  the requirements files.
- Relationship (per docs): the three artifacts are regenerated "in lockstep" by
  `just compile` so they agree on shared versions
  (`docs/architecture.md:1217-1222`, `docs/overview.md:67`). `requirements.txt` ←
  runtime deps (empty); `requirements-dev.txt` ← `--all-extras` (includes `test`);
  `uv.lock` ← `uv lock --upgrade`.
- Build backend: hatchling; version is dynamic from `modernpackage/__init__.py`
  (`pyproject.toml:17`, `45-54`).

## Q2: Justfile recipes and the exact `uv` subcommands + dependency order

All recipes are in `Justfile`. The central prerequisite is `sync`.

- `lifecycle` (`Justfile:1-4`): `uv pip sync requirements-dev.txt`; then
  `uv pip install -e .[test]`; then loops `uv run lifecycle --max-tasks 1 ...`.
- `vision` (`Justfile:6-7`): `uv run vision`.
- `sync` (`Justfile:9-11`): `uv pip sync requirements-dev.txt` **then**
  `uv pip install -e .[test]` (installs the project editable with the `test` extra).
- `test *args: sync` (`Justfile:13-14`): `uv run pytest -n "$(nproc --ignore=1)"`.
- `test-e2e *args: sync` (`Justfile:16-17`): `uv run pytest -m e2e --no-cov`.
- `format: sync` (`Justfile:19-20`): `uv run ruff format modernpackage tests`.
- `lint: sync` (`Justfile:22-23`): `uv run ruff check modernpackage tests`.
- `typecheck: sync` (`Justfile:25-26`): `uv run mypy modernpackage tests`.
- `check-format: sync` (`Justfile:28-29`): `uv run ruff format --check ...`.
- `check-lint: sync` (`Justfile:31-32`): `uv run ruff check ...`.
- `check-complexity: sync` (`Justfile:34-35`): `uv run ruff check --select C901 ...`.
- `check-typecheck: sync` (`Justfile:37-38`): `uv run mypy modernpackage tests`.
- `audit: sync` (`Justfile:40-41`): `uv run pip-audit --skip-editable`.
- `deadcode` is commented out (`Justfile:43-44`).
- `fix-lint: sync` (`Justfile:46-48`): `uv run ruff check --fix --unsafe-fixes ...`
  (deadcode line commented).
- `fix: format fix-lint` (`Justfile:50`): aggregate, no direct uv call.
- `check: check-format check-lint check-complexity check-typecheck test audit`
  (`Justfile:52`): aggregate of prerequisites; deadcode commented.
- `publish` (`Justfile:54-57`): `rm -fr dist/*`; `uv build`; `uv publish`
  (no `sync` prerequisite).
- `init package_name=...` (`Justfile:59-73`): no uv; git-grep/sed rename of
  `modernpackage`, version reset to `0.0.1`, `mv` dir, re-init git, commit.
- `compile` (`Justfile:75-78`), no `sync` prerequisite, ordered:
  1. `uv pip compile -U -q pyproject.toml -o requirements.txt`
  2. `uv pip compile -U -q --all-extras pyproject.toml -o requirements-dev.txt`
  3. `uv lock --upgrade`

Dependency-order summary: nearly every quality/test recipe depends on `sync`;
`sync` itself runs `uv pip sync` then `uv pip install -e .[test]`. `publish`,
`compile`, `init`, `lifecycle`, `vision` do **not** depend on `sync`.

## Q3: Does a Makefile exist?

### Findings
- **No Makefile exists.** `find . -iname 'Makefile'` (excluding `.venv`/`.git`)
  returns nothing.
- "make" appears only as stale/aspirational text in `README.md` Feature requests:
  `remove init Makefile alias and cli.py command python files` (`README.md:290`),
  `cd mynewpackage && make check && make publish` (`README.md:294`), and
  `make compile and make sync does not work when virtual environment is activated`
  (`README.md:300`). These reference `make` but no `Makefile` backs them; the repo
  uses the `Justfile` instead.

## Q4: How `modernpackage/main.py` reads/parses/transforms `pyproject.toml`

The CLI scaffolds a new package by cloning the template then editing its
`pyproject.toml`. It does **not** parse the project's own pyproject for deps; it
does string-replacement on the cloned template and parses only the per-user
config TOML.

### Findings
- TOML parsing via stdlib `tomllib` is used **only** for the per-user config file
  `config.toml`, not for pyproject (`main.py:7`, `_load_config_file` `main.py:273-294`).
- `_write_package_metadata` (`main.py:432-479`) edits the cloned `pyproject.toml`
  by **literal `str.replace`** of template placeholders (no TOML parse):
  - `Name Surname` → author name (`main.py:462`)
  - `email@example.com` → author email (`main.py:464`)
  - description literal `Package configuration example using bleeding edge toolset.`
    (`main.py:466-469`)
  - `_TEMPLATE_REPOSITORY_URL` `https://github.com/albertas/modernpackage`
    → repository_url (`main.py:71`, `470-474`).
- `_apply_license` (`main.py:482-497`): inserts `license = "<value>"` after
  `readme = "README.md"` and removes the classifier line
  `    "License :: OSI Approved :: MIT License",\n` — depends on those exact
  `[project]` lines / classifier (`pyproject.toml:7`, `pyproject.toml:14`).
- `_remove_project_scripts` (`main.py:531-551`): line-scans for the literal header
  `[project.scripts]\n` and deletes through to the next `[`-prefixed table; this is
  the only `[...]`-section-aware logic. It explicitly leaves `[project.urls]`,
  `[project.optional-dependencies]`, the e2e marker, the `vupi` dep, and
  `[tool.deadcode]` intact (docstring `main.py:535-538`).
- `_strip_scaffolding` (`main.py:554-571`) calls `_remove_project_scripts` and
  deletes `_SCAFFOLDING_PATHS_TO_DELETE` (`main.py:502-507`).
- No reading of `[project.optional-dependencies]` values, markers, or
  `dependencies`; the only sections the logic depends on are `[project]` keys
  (`readme`, classifiers) and the `[project.scripts]` table header.

## Q5: CI configuration — environment provisioning, dependency install, Justfile recipes called

Two CI systems exist; both delegate to the Justfile.

### Findings — GitLab (`.gitlab-ci.yml`)
- Image `python:latest` (`.gitlab-ci.yml:1`); pip cache configured
  (`.gitlab-ci.yml:5-11`).
- `before_script` (`.gitlab-ci.yml:13-17`): `pip install uv`;
  `uv tool install rust-just`; prepend `$HOME/.local/bin` to PATH; `just sync`.
- `test` job (`.gitlab-ci.yml:19-22`): re-export PATH; `just check`.

### Findings — GitHub Actions (`.github/workflows/check-modernpackage-on-python314.yml`)
- Triggers on push/PR to `main` (`...:6-10`); runs on `ubuntu-latest`, Python 3.14
  (`...:18-25`).
- Install deps step (`...:26-31`): `pip install uv`; `uv tool install rust-just`;
  add `$HOME/.local/bin` to `$GITHUB_PATH`; `just sync`.
- Run checks step (`...:32-34`): `just check`.
- Both CIs: provision uv + just, then `just sync` (install) and `just check` (gate).
  Neither runs `just compile`; pins are committed.

## Q6: How tests + docs describe/assert the dependency workflow, requirements files, `test` extra, `just compile`/`just sync`

### Findings — tests
- `tests/test_e2e.py` exercises the real flow: `git clone` the local repo →
  `_write_package_metadata` → `_strip_scaffolding` → `just init` → `just check`
  (`test_e2e.py:54-95`). Module docstring states the inner `just check` runs
  "a full `uv sync` and a networked `pip-audit`", takes minutes, and offline
  runners fail at sync (`test_e2e.py:13-15`). (Note: "uv sync" wording; the actual
  Justfile recipe is `uv pip sync` + `uv pip install -e .[test]`, `Justfile:9-11`.)
- e2e asserts the generated `pyproject.toml` keeps the license edit, drops the MIT
  classifier, removes `[project.scripts]`, and that `[project.optional-dependencies]`
  / `vupi` remain after stripping (`test_e2e.py:97-117`).
- `tests/test_main.py` asserts `_REQUIRED_TOOLS` = `('git','just','uv')` behavior
  (`test_main.py:410-536`), and that stripping preserves
  `[project.optional-dependencies]` and `vupi` (`test_main.py:1322-1329`).
- No unit test asserts `requirements.txt` / `requirements-dev.txt` / `uv.lock`
  contents directly, nor `just compile` output.
- `pyproject.toml:39-43`: pytest `addopts = "--cov=modernpackage --no-cov-on-fail
  --cov-fail-under=95.0 -m 'not e2e'"`; `e2e` marker registered.

### Findings — docs / README
- `README.md:272`: `just compile` = "bump and freeze dependency versions in
  requirements*.txt files"; `README.md:273`: `just sync` = "upgrade installed
  dependencies in Virtual Environment (executed after `just compile`)".
- `docs/overview.md:36`: `just compile` regenerates `requirements.txt`,
  `requirements-dev.txt`, `uv.lock` to latest; `docs/overview.md:51`: recipes
  depend on synced deps via `just sync` prerequisite; `docs/overview.md:67`:
  lockstep regeneration.
- `docs/architecture.md:1214-1222`: details `uv pip compile -U` for both
  requirements files (dev includes `test` extra) + `uv lock --upgrade`; notes the
  private GitLab index may lag PyPI and caps resolved versions.
- `docs/architecture.md:1261-1262`, `1275`: `sync` syncs from requirements files;
  Justfile delegates to tools via `uv run`.
- `docs/specification.md:89-92`: lists `test` group members (says `vupi>=0.0.6` —
  **stale**, actual is `vupi>=0.0.7` at `pyproject.toml:36`); describes
  `just compile` using `uv pip compile`, and the private GitLab uv index.
- `docs/specification.md:137-138`: `requirements.txt` runtime (empty),
  `requirements-dev.txt` pinned dev/test.
- `docs/invocation.md:388-392`: e2e `just check` does `uv sync` + networked
  `pip-audit`; offline fails at the `uv sync` step.

## Cross-Cutting Observations
- Single command hub: the `Justfile` is the only task runner (no Makefile);
  `sync` is the shared prerequisite and is `uv pip sync requirements-dev.txt`
  followed by `uv pip install -e .[test]` (`Justfile:9-11`).
- `uv` plays four roles: env/dependency mgmt (`uv pip sync`, `uv pip install`),
  pinning (`uv pip compile`, `uv lock`), task execution (`uv run`), and
  build/publish (`uv build`, `uv publish`).
- Two pin mechanisms coexist: `uv pip compile` requirements files (consumed by
  `uv pip sync`) **and** `uv.lock` (native), regenerated together by `compile`.
- The `test` extra is the canonical dev toolchain; `requirements-dev.txt` is its
  `--all-extras` compiled freeze.
- Required tool triplet `git/just/uv` is enforced at scaffold preflight
  (`main.py:56`, `697-708`) and re-checked in e2e (`test_e2e.py:28,55-57`).
- Docs vs reality drift: docs say "uv sync" in places where the Justfile uses
  `uv pip sync` + `uv pip install -e .[test]`; `docs/specification.md:89` lists an
  outdated `vupi>=0.0.6`.
