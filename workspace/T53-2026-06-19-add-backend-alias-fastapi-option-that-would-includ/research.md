# Research Findings

## Q1: CLI option definition/validation in `parse_args`, flags & aliases, and argument flow

### Findings
- `parse_args()` builds a single `ArgumentParser` and returns a `Namespace` (`modernpackage/main.py:347-424`).
- **store-true booleans**: `-v/--version` and `--dry-run` use `action='store_true', default=False` (`main.py:350-362`). `-v`/`--version` is the only short-alias option; aliases are expressed by passing multiple option strings to `add_argument` (`main.py:351-352`).
- **Positional**: `package_name` is positional, `nargs='?'` (optional), with `type=validate_package_name` (`main.py:363-368`).
- **Typed validators as `type=`**: `validate_package_name` (`main.py:183-196`), `validate_author_email` (`main.py:210-215`), `validate_repository_url` (`main.py:218-223`) raise `ArgumentTypeError`; argparse converts these to exit code 2 at parse time.
- **Validators**: regex-backed — `_PACKAGE_NAME_RE` (`main.py:89-92`, PEP 508), stdlib-shadow rejection via `sys.stdlib_module_names` (`main.py:101`, `main.py:190-195`), `_EMAIL_RE` (`main.py:105`), `_REPOSITORY_URL_RE` (`main.py:108`). `_explain_invalid_package_name` returns precise reasons (`main.py:161-180`).
- **Default resolution after parse**: `_resolve_metadata_defaults` fills any `None` field from env → git config → config file (`main.py:310-330`), driven by `_METADATA_FIELDS` descriptors (`main.py:148-158`). Precedence: flag > env > git config > config file (`main.py:111-130`). git_key=None encodes author-only git asymmetry (`main.py:142-147`).
- Env-sourced email/url are re-validated post-resolution via `_validated_or_error`, converting `ArgumentTypeError` to `parser.error` (exit 2) (`main.py:333-344`, `main.py:418-423`).
- **Flow**: `main()` calls `parse_args()` (`main.py:885`); if `--version`, prints and returns (`main.py:887-888`); elif `package_name` set, calls `init_new_package(...)` mapping each Namespace attr to a kwarg — note `package_license=parsed_args.license` (attr is `license`, kwarg is `package_license`) (`main.py:890-900`). `RuntimeError` from scaffolding → stderr + return 1 (`main.py:901-903`).
- `init_new_package` signature is keyword-only after `package_name` (`main.py:786-795`); flags thread into preflight, dry-run plan, metadata write, strip, and the `just init`/`just check` subprocess calls.

## Q2: Clone-and-mutate pipeline, `_strip_scaffolding`, dry-run mirroring, file-adding mechanism

### Findings
- Pipeline order in `init_new_package` (`main.py:796-880`): normalize module name (`main.py:797`) → `Path.cwd()/module_name` (`main.py:798`) → `_run_preflight_checks` (`main.py:800`) → dry-run short-circuit (`main.py:802-812`) → `git clone` via `Popen` (`main.py:814-827`) → `_write_package_metadata` (`main.py:829-836`) → `_strip_scaffolding` (`main.py:838`) → `just init <module>` (`main.py:841-859`) → `just check` (`main.py:861-880`).
- **Metadata rewrite**: `_write_package_metadata` reads cloned `pyproject.toml`, does targeted `str.replace` of known template literals (`Name Surname`, `email@example.com`, the description string, `_TEMPLATE_REPOSITORY_URL`), each TOML-escaped via `_toml_escape` (`main.py:427-479`). License handled by `_apply_license` — inserts `license = "..."` after `readme = "README.md"` and drops the MIT trove classifier (`main.py:482-497`). Missing file → notice, no raise (`main.py:452-458`).
- **File removal**: `_strip_scaffolding` (`main.py:554-571`) deletes `_SCAFFOLDING_PATHS_TO_DELETE` = `modernpackage/main.py`, `tests/test_e2e.py`, `docs`, `BACKLOG.md` (`main.py:502-507`); dirs via `shutil.rmtree(ignore_errors=True)`, files via `unlink(missing_ok=True)` (`main.py:565-568`).
- **Stub writes**: writes `tests/test_main.py` = `_TEST_MAIN_STUB` (`main.py:514-520`, `main.py:569`) and `README.md` = `_README_STUB` (`main.py:524-528`, `main.py:570`); both retain the literal `modernpackage` token so `just init`'s rename rewrites them. Then `_remove_project_scripts` deletes the `[project.scripts]` table (`main.py:531-551`, `main.py:571`).
- **Dry-run mirror**: `_format_dry_run_plan` (`main.py:599-635`) reports clone target, pyproject metadata substitutions (None → "keeps template default"), and the two documented `just init` outcomes (rename, version reset). It does **not** enumerate the strip/stub-write actions — it mirrors clone + metadata + just-init outcomes at the level the code "knows" (`main.py:609-615`).
- **Adding files**: there is **no general mechanism for adding new files/directories** into a generated package. The only files created are the two hardcoded stubs in `_strip_scaffolding` (`main.py:569-570`). Everything else is clone-then-delete/rewrite. No template-rendering, copy-tree, or scaffold-injection facility exists.

## Q3: Justfile recipe conventions, `just init` rename, token survival, new recipes & `sync`

### Findings
- **Recipe conventions** (`Justfile`): most recipes `depend on sync` (e.g. `test *args: sync`, `format: sync`, `lint: sync`) (`Justfile:14-42`). `sync` itself is `@uv sync` (`Justfile:8-9`). Recipes run tools via `uv run <tool>` (`Justfile:15,21,24,27`). Aggregate `check` chains gates: `check-format check-lint check-complexity check-typecheck test audit` (`Justfile:53`). `fix: format fix-lint` (`Justfile:51`). Variadic args via `*args` (`Justfile:14-18`). `@` silences echo; comments mark disabled deadcode recipes (`Justfile:44-49`).
- **`just init`** (`Justfile:60-74`): takes `package_name` defaulting to `modernpackage` (`Justfile:60`). Renames the token by `git grep -l 'modernpackage' | xargs sed -i 's/modernpackage/{{package_name}}/g'` — OS-branched for Linux vs Darwin (`Justfile:62-67`). Resets version to `0.0.1` in `modernpackage/__init__.py` (`Justfile:68`). `mv modernpackage {{package_name}}` (`Justfile:69`). Removes `.git/`/`.venv`, re-inits git, single commit (`Justfile:70-73`).
- **Token survival**: the scaffolder writes stubs containing the literal `modernpackage` (`_TEST_MAIN_STUB` import `from modernpackage import __version__` at `main.py:515`; `_README_STUB` heading at `main.py:525`) precisely so `git grep`/`sed` rewrites them to the new module name (`main.py:511-513`, `main.py:561-562`, `main.py:522-523`). The scaffolder's `_RESET_VERSION = '0.0.1'` is coupled by convention to `Justfile:68` (`main.py:586-588`).
- Stripping runs **before** `just init` so the rename and single commit capture an already-clean tree (`main.py:556-560`).
- New recipes follow the `<name>: sync` pattern and are added to `check`'s chain when they are gates; `sync` is the universal predecessor dependency.

## Q4: Test patterns — subprocess mocking, e2e structure, coverage/lint gates

### Findings
- **Subprocess mock attachment**: tests patch the names as imported into the module via string form `patch('modernpackage.main.Popen')` and `patch('modernpackage.main.run')` (`tests/test_main.py:292-310`); no `patch.object` form is used.
- **Popen mock pattern**: `popen_mock.return_value.returncode = 0` and `popen_mock.return_value.communicate.return_value = (b'', b'')` (stdout, stderr as bytes) (`test_main.py:296-299,329-332`). Failures set `returncode=1` and stderr bytes (`test_main.py:371-372,777-779`).
- **Multi-call sequences**: `popen_mock.side_effect = [git_clone_mock, just_init_mock, ...]` for the 3-call clone/init/check sequence (`test_main.py:378-407,746-762`); a callable side_effect records `args[0]` to assert call ordering (`test_main.py:351-359`); `FileNotFoundError('just not found')` injected as a side_effect element (`test_main.py:387`).
- **`run` mock** (for `git ls-remote`/`git config`): `MagicMock(returncode=..., stderr='...')` with stderr as plain str (text=True) (`test_main.py:793-812`); `TimeoutExpired` via side_effect (`test_main.py:1437`).
- **Real-fs fixtures**: `_seed_clone(tmp_path)` builds a real tree (modernpackage/, tests/, docs/, BACKLOG.md, README.md, pyproject copied from real repo) so `_strip_scaffolding` operates on real files (`test_main.py:1281-1295`); `_seed_pyproject` copies only pyproject for metadata tests (`test_main.py:1175-1179`).
- **e2e**: single test `test_scaffolded_package_passes_check` marked `@pytest.mark.e2e` (`test_e2e.py:53-54`); marker declared `pyproject.toml:41-43`. Skips if git/just/uv absent (`test_e2e.py:55-57`); real `git clone` of local checkout (`REPO_ROOT`), real `_write_package_metadata`/`_strip_scaffolding`, real `just init` (with injected git identity env) and `just check` (`test_e2e.py:27-95`). Asserts on real file contents (`test_e2e.py:97-116`).
- **Invocation/default exclusion**: `addopts = "--cov=modernpackage --no-cov-on-fail --cov-fail-under=95.0 -m 'not e2e'"` (`pyproject.toml:40`) — every default run excludes e2e and enforces 95% coverage. `just test-e2e` runs `uv run pytest -m e2e --no-cov` (`Justfile:17-18`).
- **Lint/type gates generated+scaffolder code must satisfy**: ruff `select = ["ALL"]` with a small ignore list (`pyproject.toml:66-73`); line-length 88 (`pyproject.toml:57`); single quotes (`pyproject.toml:59-64`); mccabe `max-complexity = 8` (`pyproject.toml:78-79`, surfaced via `check-complexity`/`--select C901` `Justfile:35-36`); mypy `strict = true`, py3.14 (`pyproject.toml:81-89`); per-file ignore for tests `S101`,`D` (`pyproject.toml:75-76`). `audit` runs `pip-audit --skip-editable` (`Justfile:41-42`).
- Test functions grouped: parse_args/flags (`test_main.py:113-277,1461-1467`), metadata default resolution incl. git-config & config-file precedence (`test_main.py:177-268,847-1133`), dry-run (`test_main.py:1450-1524`), `_strip_scaffolding` (`test_main.py:1298-1339`), `_remove_project_scripts` (`test_main.py:1342-1349`).

## Q5: `docs/` FastAPI + SQLAlchemy async + asyncpg + Alembic specification

### Findings
- **Status**: `docs/fastapi_backend.md` is a *forward-looking reference* "to prepare for a future `--backend`/`--fastapi` scaffolder option" (`fastapi_backend.md:7-8`); examples are "illustrative templates, not committed files" (`fastapi_backend.md:8`).
- **Structure**: two layouts — module-by-type (`routers/models/schemas/crud`) vs module-by-feature (`src/<feature>/{router,schemas,models,service,dependencies,config}.py`), latter recommended (`fastapi_backend.md:16-22`); `settings.API_V1_STR = "/api/v1"` versioning (`fastapi_backend.md:27`).
- **Lifespan/app factory**: `@asynccontextmanager lifespan(app)` — pre-yield `create_async_engine` + `async_sessionmaker(engine, expire_on_commit=False)` stored on `app.state.sessionmaker`; post-yield `await engine.dispose()`; `app = FastAPI(lifespan=lifespan)` (`fastapi_backend.md:53-73`). `on_event` deprecated (`fastapi_backend.md:99-101`).
- **DI**: `Annotated` idiom; `get_db` async generator yields a session from `request.app.state.sessionmaker()`; alias `DbSessionDep = Annotated[AsyncSession, Depends(get_db)]` (`fastapi_backend.md:77-95`); one session per request, not concurrency-safe (`fastapi_backend.md:162-173`).
- **Alembic**: `alembic init -t async migrations`; `env.py` bridges sync→async via `await connection.run_sync(do_run_migrations)` with `poolclass=pool.NullPool`; `DATABASE_URL` from `os.environ` not `alembic.ini` (`fastapi_backend.md:223-255`); deterministic `MetaData(naming_convention=...)` (`fastapi_backend.md:284-299`); commands `alembic upgrade head` / `revision --autogenerate` / `check`, wrapped as `just migrate`/`makemigration`/`migration-check` (`fastapi_backend.md:304-312`).
- **Migration safety**: never migrate at app startup with multiple replicas; use one-shot `migrate` service running `alembic upgrade head`, app `depends_on` it via `service_completed_successfully`, on a `NullPool` non-pooled connection bypassing pgBouncer (`fastapi_backend.md:355-366`).
- **Health checks**: `GET /livez` — no DB, returns `{"status":"pass"}` 200 (`fastapi_backend.md:469-481`); `GET /readyz` — `SELECT 1` via `engine.connect()` under `asyncio.timeout(2.0)`, returns 200 pass or `JSONResponse({"status":"fail"}, 503)` (`fastapi_backend.md:482-495`); `-z` Kubernetes suffix, `/healthz` deprecated, media type `application/health+json` per IETF draft (`fastapi_backend.md:523-528`).
- **Dependency groups**: distinguishes PEP 735 `[dependency-groups]` (local) vs PEP 621 `[project.optional-dependencies]` (published); cites existing repo PEP 735 form at "`pyproject.toml:27-37`" (`fastapi_backend.md:325-334`). `uv add [--dev|--group X|--optional X]` and `uv sync --locked/--frozen`, `uv lock --check` (`fastapi_backend.md:328-340`). No concrete `--backend` dependency-group name is enumerated.
- **Cross-refs**: top link to `overview.md` (`fastapi_backend.md:3`); defers container/compose/migration-gating to `containerization.md` (`fastapi_backend.md:9-10,346-352,532-534`). `overview.md` doc-index table links to architecture/specification/containerization/fastapi_backend (`overview.md:24-28`). **overview.md does not mention a `--backend`/`--fastapi` CLI option** — that intent lives only in `fastapi_backend.md:7-8`.

## Q6: `docs/containerization.md` — Containerfile, compose stack, migration gating, healthchecks

### Findings
- **Status**: no `Containerfile`/`compose.yml`/`.dockerignore` exist in-repo; all examples illustrative (`containerization.md:5-9`).
- **Containerfile**: base `python:3.x-slim` (Alpine discouraged) pinned `python:3.14-slim` (`containerization.md:22-24,77`); uv copied via `COPY --from=ghcr.io/astral-sh/uv:0.5 /uv /uvx /bin/` (`containerization.md:15-18,78`); multi-stage builder runs `uv sync`, runtime gets only `.venv/` (`containerization.md:28-30`); two-phase layer caching `uv sync --locked --no-install-project --no-dev` then `COPY . /app` + `uv sync --locked --no-dev --no-editable` (`containerization.md:34-40,84-91`); build env `UV_COMPILE_BYTECODE=1`, `UV_LINK_MODE=copy`, `UV_PYTHON_DOWNLOADS=0` (`containerization.md:50-53,79-81`); runtime `ENV PATH="/app/.venv/bin:$PATH"` (`containerization.md:57-64,96`); `CMD ["modernpackage", "--help"]` (`containerization.md:97`); `.dockerignore` adds `.git,__pycache__,*.pyc,.ruff_cache,.mypy_cache` (`containerization.md:42-45`).
- **Compose stack**: services `app` + `db` (`containerization.md:317-341`); app `build: .`, `ports: 127.0.0.1:8000:8000`, `DATABASE_URL=postgresql://appuser:secret@db:5432/appdb`, `depends_on.db.condition: service_healthy` (`containerization.md:318-326`); db `image: docker.io/library/postgres:17`, `POSTGRES_USER/PASSWORD/DB`, volume `pgdata:/var/lib/postgresql/data` (`containerization.md:327-340`); top-level `volumes: pgdata:` (`containerization.md:341-342`); no `version:` key (`containerization.md:273-276,314`).
- **Migration-gating ordering**: `depends_on` + `condition: service_healthy` for normal deps; `condition: service_completed_successfully` for one-shot init/migration containers (waits for exit 0) (`containerization.md:296-305`). The migration service is described in prose but **not shown** in the illustrative compose file.
- **Healthchecks**: Postgres — `test: ["CMD-SHELL","pg_isready -U appuser -d appdb"]`, `interval:10s timeout:5s retries:5 start_period:30s` (`containerization.md:333-338`). App — Dockerfile `HEALTHCHECK` using stdlib `urllib.request.urlopen('http://localhost:8000/health',timeout=4)`, `--interval=30s --timeout=5s --start-period=20s --retries=3`; `/health` returns 200 ready / 503 when deps down; exit codes 0 healthy/1 unhealthy/2 reserved (`containerization.md:243-256`).
- **Cross-refs**: does not name `fastapi_backend.md`; references the scaffolder as "the scaffolder's future service backend" (`containerization.md:8`) and "for the upcoming service backend" (`containerization.md:243`).

## Cross-Cutting Observations
- The scaffolder is strictly **clone → mutate-in-place (delete + rewrite + 2 hardcoded stubs) → `just init` rename → `just check`**; there is no facility to add directories/files beyond stubs (Q2), so a FastAPI backend's app/migrations/compose files have no existing injection path.
- The literal token `modernpackage` is the shared contract between the scaffolder's written stubs and `Justfile:62-67`'s rename sed; `_RESET_VERSION='0.0.1'` is convention-coupled to `Justfile:68` (Q3).
- Docs treat `--backend`/`--fastapi` as future and consistently distinguish PEP 735 dev `[dependency-groups]` (existing, `pyproject.toml:27-37`) from PEP 621 optional-dependencies; both `fastapi_backend.md` and `containerization.md` agree migrations run as a one-shot service gated by `service_completed_successfully`, and align on a DB-touching readiness/`/health` endpoint returning 503 on failure.
- Mocking convention: patch `modernpackage.main.Popen`/`run` by module-qualified string; pure-fs functions are tested against real `tmp_path` trees; e2e is the only real-subprocess path and is excluded by default (Q4).

## Open Areas
- Docs specify a `/health` (containerization) vs `/livez`+`/readyz` (fastapi_backend) naming difference; both exist but the docs do not reconcile which the scaffolder would emit.
- No doc enumerates the exact dependency-group **name** or package list a generated backend would add (Q5) — only the PEP 735/621 mechanism and `uv add` form.
- The dry-run plan does not currently describe strip/stub-write/add-file actions (Q2); how a backend option would surface in dry-run is unspecified in the codebase.
