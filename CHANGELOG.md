# Changelog

## 0.0.12
- T70: During package instantiation the CLI runs `just check` on the freshly scaffolded package. Add a step that runs the package's `just compile` (uv lock) and `just sync` (uv sync) targets first, so the lockfile is regenerated and dependencies are synced before `just check` runs. This avoids check failures caused by a stale lockfile after the package is renamed/modified during scaffolding.
- T71: When the scaffolder instantiates a new package, the operational/process artifacts — the `errors`, `issues`, and `workspace` directories plus the `lifecycle_state.yml` and `metrics.yml` files — must not be carried into the generated package. Extend the end-to-end test that inspects a freshly scaffolded package so it asserts these directories and files are absent, since they are currently still observed in newly created packages.
- T72: When scaffolding a new package, the generated README's top section should reflect the newly created package's name instead of the literal "modernpackage" placeholder. This makes the initialized package's documentation immediately correct for the user without manual editing.
- T73: Include the newly-bumped version number in the "Bump version" git commit message produced by the `publish` recipe in the Justfile (e.g. "Bump version to 1.2.3"). This makes each release commit self-describing about which version it publishes.
- T74: After scaffolding a new package, `init_new_package` currently runs `just check` automatically in the generated project, which is slow and can fail. Change it so that instead of running `just check`, the CLI prints a next-step command telling the user to cd into the new project directory and run `just check` themselves.
